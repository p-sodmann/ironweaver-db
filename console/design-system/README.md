# The IronWeaver::DB design system, vendored

The console's look and its components come from the IronWeaver::DB design system (a Claude design-system artifact, `https://claude.ai/artifact/RPR5vLwjF99Jh2n7PrH3xn`, version `1791113553-829a` of 2026-10-04). Its README (the brand book: principles, voice, layout, colour, type, motion) is the reference for anything the console adds; read it there.

| File | What | Edit? |
|---|---|---|
| `tokens.json` | The tokens, as the design system keeps them | Copied as is. To take a newer version, copy it again |
| `tokens.css` | Every token as a CSS custom property, light and dark (the OS setting, or `data-theme` on `<html>`) | Generated by `npm run build` from `tokens.json` |
| `src/index.jsx` | The components' source | Copied, with the console's changes below |
| `bundle.js` | The components, one classic script that sets `window.IronWeaver` (needs React 18 on `window`) | Generated by `npm run build` (esbuild, as the design system builds it) |
| `bundle.css` | The components' stylesheet | Copied, with its Google Fonts import replaced (marked `console:` at the top) and a marked `console:` section at the end |
| `fonts/` | Archivo (variable) and IBM Plex Mono 400 and 500, latin and latin-ext, as woff2 from Fontsource 5.3.0, with their SIL Open Font License 1.1 (`OFL-*.txt`) | Copied. The design system loads them from Google Fonts; the console serves them itself, so a browser contacts no third party (step 15c) |
| `index.d.ts` | The components' props, as the design system documents them | Copied as is (it doesn't list the console's props; the source comments do) |

The design system's own `tokens.css` was older than its `tokens.json` (a different palette), so the console generates its own from `tokens.json`.

## The console's changes

The design system's components run on demo data (a clinical graph, Cypher queries). The console needs them to show a real graph, so it adds optional props. Left out, each component behaves as the design system's; every change is marked `console:` in `src/index.jsx`, so they can go back into the design system as they are.

| Component | Added | Why |
|---|---|---|
| (module) | `setLabels({Label: {shape, color}})` | The labels a graph uses, in place of the demo's |
| `GraphCanvas` | `neighbours(id)`, `onConnect`, `onDetach`, `connectType` | Peek and expand show the real neighbourhood (fetched once per node) instead of made-up nodes; connect and detach are reported, to be staged |
| `Inspector` | `properties`, `relationships`, `storage`, `readOnly`; "+ Add property" opens a key/value row | The node's own attributes and degree; staged values marked (`dirty`) |
| `ResultTable` | `pager`, `onExport`, `emptyTitle`, `emptyBody`; rows keep their order until a header is clicked; numbers sort as numbers | The demo sorted by its 4th column and broke on narrower results |
| `PlanView` | `summary`, `hint`; starts on the first hot operator | Our explain reports candidates, not Neo4j's db hits |
| `QueryConsole` | `params`, `keywords`, `minRunMs`, `comment`; a new `query` replaces the text; a failed run returns the cap to rest | The shell's commands and `--` comments instead of Cypher |
| `StatusRail` | `drawer`, `footer`, `children`, `onDb`, `word` | Our instruments and words; page links; the namespace switcher |
| `SchemaNavigator` | `stateLabel` on items | READY and BUILDING instead of ONLINE and POPULATING |
| `ShortcutSheet` | `extra` | The console's own keys |
| `bundle.css` | dirty-property marker, the add-property row, a shortcut sheet that fits more groups; `@font-face` rules for `fonts/` instead of the Google Fonts import (step 15c) | |

## Taking a newer version

1. Read the design system's `project/components/src/index.jsx`, `bundle.css` and `tokens.json`.
2. Replace `tokens.json`; merge the source and the stylesheet, keeping every `console:` change (or drop one the design system now has).
3. `npm run build`, then look at both pages in light and dark (and `?scenario=degraded`), and run `npm test`.
4. Update the version at the top of this file.
